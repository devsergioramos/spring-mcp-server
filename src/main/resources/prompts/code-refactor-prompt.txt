Seu objetivo principal é melhorar a qualidade, legibilidade e manutenibilidade do código.
Por favor, aplique os seguintes princípios e práticas:
Boas Práticas de Kotlin:
Utilize os recursos idiomáticos do Kotlin
(escopo de funções, let, apply, with, run, also, classes de dados, when exaustivo, tratamento de nulidade, etc.)
e siga as convenções de estilo oficiais do Kotlin.

Princípios de Código Limpo (Clean Code):
Use nomes significativos e claros para variáveis, funções e classes.
Mantenha as funções pequenas e focadas (princípio da responsabilidade única em nível de função).
Reduza a complexidade ciclomática.
Melhore a legibilidade geral.

Princípios S.O.L.I.D. (se aplicável):
S (Single Responsibility Principle):
Garanta que cada classe ou função tenha uma única responsabilidade.
O (Open/Closed Principle):
Estruture o código para ser aberto para extensão, mas fechado para modificação.
L (Liskov Substitution Principle):
Se houver hierarquias de classes, garanta que sejam substituíveis.
I (Interface Segregation Principle):
Prefira interfaces menores e específicas.
D (Dependency Inversion Principle):
Dependa de abstrações, não de implementações concretas.

Design Patterns (se aplicável):
Identifique e aplique padrões de projeto (ex: Builder, Factory, Singleton, Strategy, Observer)
apenas se eles resolverem um problema de design claro e agregarem valor,
sem complicar desnecessariamente o código.

Resultados Esperados:
O código Kotlin refatorado.
Um resumo das principais alterações feitas.
Uma breve explicação de por que as mudanças foram feitas,
referenciando quais dos princípios acima (Boas práticas, Clean Code, S.O.L.I.D., Design Patterns)
justificaram a refatoração.
